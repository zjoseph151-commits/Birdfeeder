# Bird Feeder Camera System - Project Summary

## Overview
Built a motion-activated bird feeder camera system using XIAO ESP32-S3 Sense that captures photo bursts and uploads them wirelessly to a PC server.

## Hardware Components
- **XIAO ESP32-S3 Sense** (with camera module)
- **HW-201 IR motion sensor** (connected to GPIO 2)
- **WiFi antenna** (essential for 2.4GHz connectivity)
- **MicroSD card** (optional - for offline storage mode)
- **Power:** 5V via 5V pin and GND (bypasses USB for battery operation)

## Final Implementation
**Two Code Versions Created:**

### Version 1: WiFi Photo Burst (Deep Sleep) - Primary Version
- Motion-triggered photo capture
- Captures 5 JPEG images, 5 seconds apart
- Uploads directly to PC server via WiFi (no SD card needed)
- Deep sleep between motion events (~50mA sleep, ~130mA active)
- Serial1 debug output (TX on GPIO 43)
- Photos saved to PC: `bird_0_photo1.jpg`, `bird_0_photo2.jpg`, etc.

### Version 2: SD Card Only (Offline)
- Records videos/photos to SD card
- No WiFi required
- Manual retrieval of SD card for viewing
- Backup option if WiFi unavailable

## Arduino IDE Configuration (Critical)
**Required settings for successful compilation and operation:**
- **Board:** XIAO_ESP32S3
- **PSRAM:** OPI PSRAM ✓ (MUST be enabled - camera won't work without it)
- **USB CDC On Boot:** Enabled ✓ (required for Serial Monitor)
- **Partition Scheme:** Default 4MB with SPIFFS

## Python Server (PC Side)
- Simple Flask server receives photo uploads
- Runs on Windows PC at `C:\BirdFeeder\`
- Saves photos to `bird_videos` folder
- Listens on port 5000
- No web interface (simplified - just folder storage)

**To run server:**
```bash
cd C:\BirdFeeder
python bird_server.py
```

## Major Issues Solved

### 1. Camera Initialization Failed (Error 0xffffffff)
**Problem:** Memory allocation failure  
**Solution:** Enable "OPI PSRAM" in Arduino IDE Tools menu  
**Why:** ESP32-S3 camera requires PSRAM for frame buffers

### 2. WiFi Connection Failed (Status 6)
**Problem:** Could not connect to WiFi network  
**Root causes discovered:**
- 5GHz network (ESP32 only supports 2.4GHz)
- Missing/faulty WiFi antenna
**Solution:** 
- Use 2.4GHz WiFi network
- Ensure antenna is properly attached

### 3. SD Card Mount Failed
**Problem:** SD card not accessible  
**Solutions tried:**
- Wrong partition scheme → Changed to one with SPIFFS support
- Wrong SD library mode → Switched from SD_MMC to SPI mode
- Incorrect pins → Used correct SPI pins (CS=21, MOSI=9, MISO=8, SCK=7)

### 4. Video Playback Issues (Videos Appeared as Single Frames)
**Problem:** MJPEG videos wouldn't play properly in VLC  
**Root cause:** Attempting to create video files was complex and unreliable  
**Solution:** **Switched to individual JPEG photos** instead of video
- Much simpler and more reliable
- 5 separate .jpg files per motion event
- Easier to view and share

### 5. Upload Failures (0 Byte Files)
**Problem:** Files uploaded but were empty  
**Root causes:**
- SPIFFS filled up (only ~1.4MB available)
- Trying to stream in real-time caused incomplete transfers
**Solution:** 
- Collect all frames in RAM buffer first
- Upload complete buffer as single POST request
- Switch to SD card for larger storage capacity

### 6. IR Sensor Constantly Triggering
**Problem:** Sensor showed HIGH on boot, recorded continuously  
**Investigation:** Not fully resolved - sensor may be inverted or wiring issue  
**Workaround:** Used test timer mode (15-30 second intervals) during development  
**Final behavior:** Sensor works correctly (HIGH=idle, LOW=motion detected)

### 7. Deep Sleep Power Consumption Too High
**Problem:** Expected ~10μA sleep, getting ~50mA  
**Attempts to fix:**
- Power down camera with `esp_camera_deinit()`
- Disable WiFi and Bluetooth completely
- Set camera GPIO pins to input with pulldowns
**Result:** Could not reduce below 50mA
**Likely cause:** Camera hardware module stays partially powered (hardware limitation, not code)  
**Conclusion:** 50mA is acceptable for bird feeder use case (still 3x better than active mode)

## Key Technical Learnings

### WiFi Requirements
- ESP32 **only supports 2.4GHz**, not 5GHz
- Antenna **must be attached** for reliable connection
- Network must use WPA2 (WPA3 may cause issues)

### Memory Management
- PSRAM essential for camera operation
- SPIFFS limited (~1.4MB) - not suitable for video storage
- SD card provides ample space (GB range)
- RAM buffer approach works for photo bursts

### Power Optimization
- Deep sleep theoretical: ~10μA
- Achieved in practice: ~50mA (camera module limitation)
- Active mode: ~130mA
- Battery life acceptable for periodic operation (days with typical use)

### Serial Debugging
- Serial1 (GPIO 43 TX, GPIO 44 RX) used instead of USB Serial
- Allows debugging without USB connection
- Essential for battery-powered operation testing

## Code Architecture

### WiFi Photo Burst Flow:
1. **Deep sleep** (waiting for motion)
2. **IR sensor triggers** (LOW signal)
3. **Wake up** from deep sleep
4. **Initialize camera** and connect to WiFi
5. **Capture 5 photos** (5 seconds apart, ~25 seconds total)
6. **Upload each photo** immediately via HTTP POST
7. **Wait for sensor to return to idle** (HIGH)
8. **Return to deep sleep**
9. Repeat on next motion

### Key Code Features:
- `RTC_DATA_ATTR` - Preserves burst counter across sleep cycles
- `esp_sleep_enable_ext0_wakeup()` - Wake on GPIO change
- `esp_deep_sleep_start()` - Enter low power mode
- HTTPClient streaming - Efficient photo upload
- Error handling - Falls back to timer wakeup if sensor issues

## Network Configuration
**Current Setup:**
- SSID: User's 2.4GHz network
- Server IP: Dynamic (user must update in code)
- Port: 5000
- Protocol: HTTP POST with custom headers

## File Naming Convention
**WiFi Mode:** `bird_X_photoY.jpg`
- X = burst number (0, 1, 2...)
- Y = photo within burst (1-5)

**SD Card Mode:** `video_X.mjpeg`
- Sequential numbering
- Playable in VLC

## Quick Start Guide

### Hardware Setup:
1. Attach WiFi antenna to XIAO ESP32-S3
2. Connect HW-201 OUT → GPIO 2, VCC → 3.3V, GND → GND
3. Insert microSD card (optional, for backup mode)
4. Power via 5V pin + GND (battery) or USB-C (testing)

### Software Setup:
1. Arduino IDE: Select XIAO_ESP32S3 board
2. Enable OPI PSRAM and USB CDC On Boot
3. Update WiFi credentials in code (lines 38-39)
4. Find PC IP address (`ipconfig` in Windows)
5. Update serverUrl in code (line 42)
6. Upload to ESP32

### Server Setup:
1. Install Python: `pip install flask`
2. Save `bird_server.py` to `C:\BirdFeeder\`
3. Run: `python bird_server.py`
4. Photos save to `C:\BirdFeeder\bird_videos\`

### Testing:
1. Monitor current draw with ammeter
2. Trigger IR sensor manually
3. Verify 5 photos upload to server folder
4. Check sleep current drops to ~50mA
5. Deploy to bird feeder location
